# 数据库表结构设计 (专家级方案)

数据库名建议设为：`ops_twin_db`。

## 1. 系统管理模块 (System Management)
### 1.1 用户表 (sys_user)
- id, username, password, avatar, role_id, status(1正常/0禁用)

### 1.2 菜单与权限表 (sys_permission)
- id, parent_id, title, path(路由), component(组件路径), icon, type(1菜单/2按钮), permission_code(权限标识)

### 1.3 操作审计日志表 (audit_event)
- id, user_id, action, target, detail, create_time

## 2. 资产中心模块 (Asset Center - CMDB)

### 2.1 物理机柜表 (asset_cabinet)
> 架构重构亮点：提取机柜作为独立物理载体，规范机房坐标系
- id, cabinet_id(编号), cabinet_name(名称), pos_x, pos_z(物理空间坐标), max_u(最大U位，默认42)

### 2.2 物理服务器表 (asset_host)
- id, hostname, ip_addr, status(1健康/2报警/3宕机/0离线), cpu_cores, memory_gb
- cabinet_id(关联 asset_cabinet 的编号), rack_pos(机架插槽位置)
- *注：物理坐标由关联的机柜决定，实现数据归一化。*

### 2.3 逻辑服务表 (asset_service)
> 亮点所在：实现“逻辑”与“物理”的解耦
- id, service_name, owner, description

### 2.4 服务-主机映射表 (service_host_map)
- id, service_id, host_id

## 3. 任务中心模块 (Task Center)

### 3.1 演练预案表 (strategy_plan)
- id, plan_name, description, steps_json (以 JSON 存储步骤流)

### 3.2 模拟任务流水表 (pipeline_record)
- id, plan_id, target_node_id, operator_id, start_time, end_time, status(SUCCESS/FAIL/RUNNING)

### 3.3 终端日志存根表 (pipeline_log)
- id, task_id, log_content, level(INFO/WARN/ERROR), create_time

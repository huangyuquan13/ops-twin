# 数据库表结构设计 (专家级方案)

数据库名建议设为：`ops_twin_db`。

## 1. 系统管理模块 (System Management)

### 1.1 用户表 (sys_user)
- id, username, password, avatar, role_id(1管理员/2普通用户), create_time

### 1.2 角色表 (sys_role) ✔Stage4新增
- id, role_name, role_code, description, create_time

### 1.3 角色-权限关联表 (sys_role_permission) ✔Stage4新增
- id, role_id, permission_id

### 1.4 菜单与权限表 (sys_permission) ✔Stage4升级
- id, parent_id, title, path(路由), component(组件路径), icon, permission_code(按钮权限标识), type(1菜单/2按钮), sort
- 按钮权限码: strategy:add/edit/delete/execute/toggle/workflow, host:add/edit/delete, cabinet:add/edit/delete, user:add/edit/delete, role:manage, service:save

### 1.5 操作审计日志表 (audit_event) ✔Stage4激活
- id, operator, event_type(LOGIN/EXECUTE_PLAN/DELETE_PLAN), detail, create_time
- *注：此表由 AOP 切面自动填充 — `@AuditLog` 注解标记在 Controller 的写入方法上，`AuditLogAspect` 环绕通知自动提取操作人 (从 Authorization 头解析 JWT)、操作类型、描述和结果 (SUCCESS/FAILED)，无需手动调用审计写入接口。*

## 2. 资产中心模块 (Asset Center - CMDB)

### 2.1 物理机柜表 (asset_cabinet)
> 架构重构亮点：提取机柜作为独立物理载体，规范机房坐标系
- id, cabinet_id(编号), cabinet_name(名称), pos_x, pos_z(物理空间坐标), max_u(最大U位，默认42)

### 2.2 物理服务器表 (asset_host)
- id, hostname, ip_addr, status(1健康/2报警/3宕机/0离线), cpu_cores, memory_gb
- host_type(WEB/APP/DB/CACHE/LB/MQ), description(用途描述)
- cabinet_id(关联 asset_cabinet 的编号), rack_pos(机架插槽位置)
- *注：物理坐标由关联的机柜决定，实现数据归一化。*
- *注2：`status` 字段由演练引擎动态修改 — DRILL 执行时主机状态变为 3(宕机)，执行结束后自动恢复为 1(健康)；FAILOVER 执行后持久化变更。*

### 2.3 逻辑服务表 (asset_service)
> 亮点所在：实现”逻辑”与”物理”的解耦
- id, service_name, owner, description, topology_json(Vue Flow拓扑数据), create_time, update_time

### 2.4 服务-主机映射表 (service_host_map)
- id, service_id, host_id
- *注：此表由演练引擎动态修改 — FAILOVER 执行时将宕机主机的服务迁移到备用主机 (修改 host_id)；SCALE 执行时动态增加或移除主机绑定。预案重置 API (`/api/task/plan/reset/{planId}`) 可将 FAILOVER/SCALE 修改的绑定关系还原。*

## 3. 任务中心模块 (Task Center)

### 3.1 演练预案表 (task_plan) ✔已建立
- id, plan_name, service_id(关联 asset_service), plan_type(DRILL/FAILOVER/SCALE)
- priority(1高/2中/3低), steps_json(执行步骤 JSON 编排), description, status(1启用/0禁用)
- create_by, create_time, update_time

### 3.2 任务执行流水表 (task_record) ✔已建立
| 字段名 | 类型 | 说明 | 约束 |
| :--- | :--- | :--- | :--- |
| id | bigint | 流水唯一ID | PK, Auto |
| plan_id | bigint | 关联的预案 ID | - |
| plan_name | varchar | 预案名称 (冗余) | - |
| service_id | bigint | 关联的服务 ID | - |
| run_status | varchar | 执行状态 (PENDING/RUNNING/SUCCESS/FAILED/CANCELLED) | - |
| duration_ms | bigint | 执行总耗时 | - |
| operator | varchar | 操作人 | - |
| result_msg | text | 执行结果简述 | - |
| start_time | datetime | 开始执行时间 | - |
| end_time | datetime | 执行结束时间 | - |
| create_time | datetime | 创建时间 | - |

### 3.3 终端日志存根表 (pipeline_log) ✔已建立
- id, task_id, log_content, level(INFO/WARN/ERROR), create_time

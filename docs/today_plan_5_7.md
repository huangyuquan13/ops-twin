## 今日核心任务：Stage 3 启动 - 预案方案库与调度基座

**目标**: 建立一套能够被调度的“容灾/演练预案”数据模型，并搭建前端的预案配置面板。

**具体工作**:

### 任务一：数据库设计与后端基座建立
- **需求**: 创建 `task_plan` (预案表) 和 `task_record` (执行流水表)。
  - `task_plan` 需包含：预案名称、绑定的逻辑服务 ID (对应 Stage 2)、预案内容 (如执行脚本或 JSON 指令集)、触发条件等。
  - `task_record` 需包含：执行状态 (运行中/成功/失败)、耗时、操作人等。
- **交付**: 
  - `ops_twin_db.sql` 增加表结构及 11 条以上测试数据。
  - 后端生成对应的 Entity, Mapper, Service, Controller。

### 任务二：预案配置中心 (Frontend)
- **需求**: 开发一个新的前端页面 `src/views/task/plan.vue` (需在数据库 `sys_permission` 中配置路由)。
- **交付**: 
  - **关联业务**：在新增预案时，必须选择一个“逻辑服务”（如下拉选择“支付网关”），体现 CMDB 数据对自动化任务的支撑。
  - **预案管理**：实现对演练预案的 CRUD（增删改查及分页）。
  - 界面风格需保持与之前一致的高级感与玻璃质感。

### 任务三：WebSocket 日志通道预研 (核心筹备)
- **需求**: 真实演练需要实时反馈执行进度，普通的 HTTP 轮询无法满足“炫酷大厂风”。我们需要在 Spring Boot 中集成 `spring-boot-starter-websocket`。
- **交付**: 建立一个 `/ws/task/log/{taskId}` 的双向通讯管道，为后续前端集成 `Xterm.js` 控制台打下坚实基础。

## 成功标准 (DoD)
1. 前端页面能够正常展示预案列表（包含造好的测试数据验证分页）。
2. 在页面上能够为“核心支付网关”成功创建一个名为“数据库主从切换测试”的演练预案，并存入数据库。
